# 开发流程补充

## Worktree 隔离与主分支汇总

- 所有功能开发和缺陷修复都必须使用独立 Git worktree；主工作区只用于汇总、推送和触发部署，不直接开发。
- worktree 统一创建在仓库根目录的 `.worktree/<功能名>/` 下，一个子目录只承载一个功能分支；`.worktree/` 必须被 Git 忽略，禁止提交其中内容。
- 创建 worktree 前先获取远端最新状态，并从最新的 `origin/main` 创建独立临时分支。不同功能可以并行开发，彼此不得复用目录、分支或未提交改动。
- 功能完成后，先获取最新的 `origin/main`，将功能分支 rebase 到其上并重新验证；若有冲突，只在功能分支中解决，不得让旧基线直接进入 `main`。
- 多个功能的开发可以并行，但集成、推送和部署必须逐个串行：将一个已验证的功能以 fast-forward-only 方式汇入本地 `main`，推送到远端仓库并确认远端 `main` SHA 后，下一个功能必须重新基于这个最新 `main` 完成 rebase、验证和汇入。
- 只有远端仓库的 `main` 已包含目标提交后，才允许基于该最新 `main` 执行自动部署。服务器不得从功能分支、旧提交或未推送的本地代码部署。
- 准备部署时若发现服务器已有部署任务正在运行或部署锁已被占用，必须等待该任务完整结束并确认锁已正常释放后再开始；等待期间不得同步服务器源码、并发部署、抢占或删除他人的部署锁。前一个部署结束后，还必须重新确认远端最新 `main` 和待部署提交一致。
- 服务器源码同步、部署锁、构建、健康检查、验收、失败恢复和 worktree 清理等细节，统一遵循仓库根目录 `AGENTS.md`；若其中的 worktree 路径约定与本文件冲突，以本文件的 `.worktree/` 约定为准。

## 客户交付文档

- 客户交付文档的唯一内容源位于 `docs/deliverables/`；这里的 Markdown 必须使用客户视角和可直接交付的语言，不得混入内部开发备注、未实现规划或真实密码、令牌和密钥。
- 功能、配置、依赖、端口、权限、部署方式或客户操作流程发生变化时，必须在同一功能改动中同步更新受影响的交付 Markdown，保证文档只描述当前已经实现并验证的逻辑。
- 交付前必须执行 `make docs`，确认 `dist/DocuMind项目交付文档书/` 中的 Word 和 `dist/YYYYMMDD-DocuMind项目交付文档书.zip` 均可正常生成。
- `dist/` 中的 Word 和压缩包是生成物，不提交 Git，也不得手工修改；内容变更回到 `docs/deliverables/`，统一版式或图表变更回到 `scripts/build-docs.py`。
