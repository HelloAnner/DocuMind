# DocuMind 独立部署说明书

> [!重要] 本说明书用于指导客户在自有内网服务器上部署 DocuMind。实际地址、账号、密码和模型参数应由客户项目负责人及实施人员共同确认，本文示例值不可直接用于生产环境。

## 文档说明

DocuMind 是面向企业知识管理场景的文档智能问答系统。系统可以部署在客户自有网络中，由客户控制用户、文档、业务数据和运行环境。员工通过浏览器访问系统，完成知识库管理、文档上传、内容检索和带原文引用的智能问答。

本文从客户使用和验收角度说明部署边界、环境准备、安装配置、上线检查及日常运维。部署实施前，建议由以下人员共同确认：

- 客户项目负责人：确认上线范围、使用人数和验收标准。
- 系统管理员：准备服务器、域名、证书、账号及备份空间。
- 网络与安全人员：确认访问边界、防火墙和密钥管理要求。
- DocuMind 实施人员：完成安装、配置、数据初始化和联合验收。

## 独立部署边界

### 客户能够控制的内容

独立部署后，以下内容均处于客户指定的内网环境或客户认可的服务边界内：

- DocuMind 应用服务及管理页面。
- 用户、租户、角色、知识库和会话记录。
- 上传的原始文档、解析结果和检索索引。
- 数据库、缓存、消息队列、对象存储及日志。
- 大语言模型、向量模型和重排模型的接入地址与密钥。

DocuMind 应用以一个服务进程对外提供前端页面和 API，默认监听 `8089` 端口。客户无需单独部署前端站点。

### 必要的配套能力

“独立部署”表示系统可运行在客户指定的内网机器上，不表示系统完全没有外部依赖。完整问答和文档处理需要以下配套能力：

| 能力 | 主要用途 | 部署选择 |
|---|---|---|
| PostgreSQL | 保存用户、权限、知识库、文档元数据、会话和审计数据 | 可与应用同机，也可使用客户现有数据库服务 |
| Elasticsearch | 保存文档全文及向量索引，提供混合检索 | 建议使用独立实例或客户统一搜索服务 |
| MinIO 或兼容 S3 的对象存储 | 保存原始文件、预览文件及处理产物 | 可同机部署，也可接入客户对象存储 |
| Redis | 缓存、短期状态和并发控制 | 小规模环境可同机部署 |
| RabbitMQ | 文档向量任务通知与可靠处理 | 小规模环境可同机部署 |
| LLM、Embedding 与 Reranker | 问题理解、答案生成、语义检索和结果重排 | 可接入客户内网模型服务或经批准的兼容接口 |

> [!提示] 对数据不出内网有严格要求时，LLM、Embedding 和 Reranker 也必须部署在客户认可的网络边界内。实施前应完成模型效果、并发能力和合规性验证。

## 推荐部署架构

### 系统访问关系

```flow
企业员工浏览器|HTTPS 访问|DocuMind 应用服务
DocuMind 应用服务|业务数据|PostgreSQL
DocuMind 应用服务|检索与向量索引|Elasticsearch
DocuMind 应用服务|原始文件与预览|MinIO / S3
DocuMind 应用服务|缓存与任务协调|Redis / RabbitMQ
DocuMind 应用服务|模型推理请求|LLM / Embedding / Reranker
```

生产环境建议仅向用户网络开放统一访问入口，其余组件只允许 DocuMind 应用服务器访问。数据库、搜索、缓存、队列和对象存储端口不应直接暴露给终端用户。

### 部署方式选择

| 方案 | 适用场景 | 说明 |
|---|---|---|
| 单机一体化 | 试用、验证、小规模使用 | 应用和基础组件位于同一台服务器，交付简单；需重点关注磁盘容量和备份 |
| 应用与数据分离 | 正式生产、数据量持续增长 | 应用独立部署，数据库、搜索和对象存储使用独立服务器或客户现有平台 |
| 高可用扩展 | 高并发或关键业务 | 在容量评估后增加应用实例及基础组件高可用能力，不属于首版单机部署的默认范围 |

首期建议从满足实际人数和文档量的最小方案开始。只有监控数据表明容量不足时，再扩展节点，避免提前增加运维复杂度。

## 部署前准备

### 服务器建议

以下配置用于项目启动阶段的容量规划，不作为固定上限。最终规格应结合文档总量、每日新增量、并发用户数、模型部署方式和备份周期确认。

| 使用规模 | CPU | 内存 | 可用磁盘 | 建议用途 |
|---|---:|---:|---:|---|
| 验证环境 | 8 核 | 16 GB | 200 GB | 功能确认、小批量文档和低并发验证 |
| 常规生产起步 | 16 核 | 32 GB | 500 GB 起 | 应用与基础组件同机的中小规模使用 |
| 数据服务分离 | 应用节点 8 核起 | 应用节点 16 GB 起 | 按组件分别规划 | 文档量持续增长或需要独立备份策略的环境 |

- 操作系统建议使用受客户支持的 64 位 Linux，CPU 架构为 x86_64。
- 文件系统应预留应用发布、日志、对象文件、搜索索引及备份空间。
- 服务器时间应接入客户统一 NTP，避免审计时间和令牌有效期异常。
- 生产环境应配置固定 IP 或稳定域名，不建议使用临时地址。
- 如基础组件采用容器运行，应预先安装客户批准的 Podman 或 Docker。

### 网络与端口

| 端口 | 服务 | 访问方 | 开放建议 |
|---:|---|---|---|
| 8089 | DocuMind 页面与 API | 用户浏览器或内网反向代理 | 对授权用户网段开放；正式环境建议由 HTTPS 入口代理 |
| 5432 | PostgreSQL | DocuMind 应用 | 仅应用服务器可访问 |
| 9200 | Elasticsearch | DocuMind 应用 | 仅应用服务器可访问 |
| 9000 | MinIO / S3 API | DocuMind 应用 | 仅应用服务器可访问 |
| 6379 | Redis | DocuMind 应用 | 仅应用服务器可访问 |
| 5672 | RabbitMQ | DocuMind 应用 | 仅应用服务器可访问 |
| 客户指定 | 模型服务接口 | DocuMind 应用 | 仅允许访问已批准的模型地址 |

如果使用反向代理，客户应同时确认访问域名、TLS 证书、上传文件大小限制、请求超时时间和 SSE 流式响应支持。

### 上线前信息确认表

| 项目 | 客户需要提供或确认的内容 |
|---|---|
| 访问入口 | 域名、IP、HTTPS 证书及允许访问的用户网段 |
| 身份认证 | 使用 DocuMind 独立账号体系，或明确启用门户登录模式 |
| 初始管理员 | 管理员姓名、账号和安全的初始密码交付方式 |
| 数据服务 | PostgreSQL、Elasticsearch、MinIO/S3、Redis、RabbitMQ 的地址和账号 |
| 模型服务 | LLM、Embedding、Reranker 的接口地址、模型名、密钥和并发限制 |
| 数据规模 | 初始文档数量、预计容量、单文件上限和每日增量 |
| 运维要求 | 日志保留期、备份周期、恢复目标、监控和告警接收人 |

## 交付物核对

文档交付包与软件部署包可以分别提供。实施人员应在安装前核对软件部署包至少包含以下内容：

- 与客户服务器架构匹配的 DocuMind 应用程序。
- 环境配置模板及本次交付对应的版本标识。
- 文件校验值或客户认可的完整性校验方式。
- 本说明书及项目约定的其他交付文件。

> [!重要] 本文档压缩包只包含交付文档，不包含应用程序、模型文件、客户密码或其他密钥。软件部署包和敏感配置应通过双方约定的安全渠道单独交付。

## 安装与配置

### 建议目录

```text
/opt/documind/
├── current/                 当前运行版本
├── releases/                历史发布版本
└── shared/
    ├── .env                 客户环境配置
    ├── data/                持久化数据或组件挂载目录
    ├── logs/                应用日志
    └── runtime/             运行状态文件
```

应用版本与持久化数据应分离。升级时只替换应用版本，不覆盖 `.env`、日志和数据目录。

### 核心配置

以下内容为配置示例，实际值必须替换。密钥不得提交到代码仓库、文档或工单正文中。

```env
SERVER_HOST=0.0.0.0
SERVER_PORT=8089
DATABASE_URL=postgres://USER:PASSWORD@postgres-host:5432/documind
ELASTICSEARCH_URL=http://elasticsearch-host:9200
OBJECT_STORAGE_PROVIDER=minio
OBJECT_STORAGE_ENDPOINT=http://minio-host:9000
OBJECT_STORAGE_BUCKET=documind
OBJECT_STORAGE_ACCESS_KEY=REPLACE_ME
OBJECT_STORAGE_SECRET_KEY=REPLACE_ME
REDIS_URL=redis://:PASSWORD@redis-host:6379/0
RABBITMQ_URL=amqp://USER:PASSWORD@rabbitmq-host:5672/%2f
USE_REAL_LLM=true
LLM_BASE_URL=http://llm-host/v1
LLM_API_KEY=REPLACE_ME
LLM_MODEL=REPLACE_ME
EMBED_ENABLED=true
EMBED_BASE_URL=http://embedding-host/v1
EMBED_API_KEY=REPLACE_ME
EMBED_MODEL=REPLACE_ME
EMBED_DIM=1024
RAG_RERANK_API_URL=http://reranker-host/rerank
RAG_RERANK_API_KEY=REPLACE_ME
RAG_RERANK_MODEL=REPLACE_ME
JWT_SECRET=REPLACE_WITH_AT_LEAST_32_RANDOM_BYTES
AUTH_LOGIN_MODE=local
RUST_LOG=documind=info,tower_http=info
LOG_FORMAT=json
```

配置时应特别注意：

- `JWT_SECRET` 必须使用生产环境专用的高强度随机值。
- `EMBED_DIM` 必须与向量模型实际输出维度和 Elasticsearch 索引一致。
- `USE_REAL_LLM` 在生产环境必须为 `true`，不得使用演示或模拟回答。
- 默认推荐 `AUTH_LOGIN_MODE=local`，使用 DocuMind 自身账号体系；只有项目明确接入门户时才改为 `portal`。
- 对象存储 Bucket、数据库和组件账号应使用 DocuMind 专用权限，避免与其他系统共用高权限账号。
- 生产配置文件权限应限制为运行账号可读，不应允许普通用户查看。

### 部署执行顺序

```flow
准备服务器与网络|完成后|部署并检查基础组件
部署并检查基础组件|连接正常后|配置 DocuMind 与模型服务
配置 DocuMind 与模型服务|校验通过后|启动应用并执行健康检查
启动应用并执行健康检查|服务正常后|创建管理员并上传验收文档
创建管理员并上传验收文档|问答与引用通过后|完成上线确认
```

1. 创建 DocuMind 专用系统运行账号和安装目录。
2. 部署或接入 PostgreSQL、Elasticsearch、MinIO/S3、Redis 和 RabbitMQ。
3. 创建专用数据库、对象存储 Bucket 及最小权限账号。
4. 将应用程序放入新的版本目录，并核对文件完整性。
5. 将客户环境配置写入 `/opt/documind/shared/.env`，设置严格文件权限。
6. 先检查各依赖地址及账号，再启动 DocuMind 服务。
7. 配置 systemd 或客户统一进程管理平台，保证异常退出后可恢复。
8. 通过健康检查、页面访问和业务操作完成上线验证。

### 服务管理示例

具体应用路径以本次软件部署包为准。以下 systemd 示例展示必要的运行边界：

```ini
[Unit]
Description=DocuMind
After=network-online.target
Wants=network-online.target

[Service]
User=documind
Group=documind
WorkingDirectory=/opt/documind/current
EnvironmentFile=/opt/documind/shared/.env
ExecStart=/opt/documind/current/documind
Restart=on-failure
RestartSec=5
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

启动后可在服务器内部检查：

```bash
curl -fsS http://127.0.0.1:8089/api/health
curl -I http://127.0.0.1:8089/documind/
```

健康检查应返回服务可用状态，页面入口应返回成功响应。若健康检查列出依赖异常，应先修复对应组件，不应带故障进入客户验收。

## 初始配置与业务验收

### 初始管理员

默认独立部署使用 DocuMind 自身账号体系。用户使用全局唯一的用户 ID 和密码登录，展示名称独立维护。初始管理员用户 ID 应通过安全渠道交付，并在首次登录后立即修改初始密码。管理员随后按实际组织创建用户、分配角色并授权知识库。

若项目明确启用门户登录，应单独确认门户地址、票据交换接口、用户同步规则和异常回退方案；未启用时不需要部署或连接门户系统。

### 标准验收流程

1. 使用授权账号登录，确认无权限用户无法进入管理页面。
2. 创建一个验收知识库，并只授权给指定测试人员。
3. 上传 Word、PDF 或 Markdown 验收文档，等待处理状态完成。
4. 提问文档中可以明确回答的问题，检查答案内容和原文引用。
5. 提问文档中不存在的信息，确认系统不会把无依据内容当成文档事实。
6. 打开引用定位，确认引用文档、片段和用户权限正确。
7. 检查会话历史、反馈记录、服务日志和健康状态。
8. 使用未授权账号验证知识库隔离，确认无法搜索或查看无权限内容。

### 验收记录表

| 检查项 | 通过标准 | 结果 |
|---|---|---|
| 页面访问 | 授权网络可正常打开，浏览器无证书告警 | 待填写 |
| 登录与权限 | 正确账号可登录，未授权资源不可见 | 待填写 |
| 文档上传 | 验收文件上传成功并完成处理 | 待填写 |
| 文档问答 | 回答与文档一致，包含可用引用 | 待填写 |
| 无答案场景 | 没有依据时明确说明，不能伪造引用 | 待填写 |
| 数据隔离 | 不同用户和知识库权限符合约定 | 待填写 |
| 健康检查 | 必要组件全部正常，无持续错误日志 | 待填写 |
| 重启恢复 | 应用重启后可恢复服务，历史数据保留 | 待填写 |
| 备份恢复 | 完成至少一次备份并验证恢复步骤 | 待填写 |

## 安全要求

- 用户访问建议统一使用 HTTPS，并由客户证书体系管理证书更新。
- 数据库、搜索、缓存、消息队列和对象存储端口不得直接对办公终端开放。
- 数据库密码、模型密钥、JWT 密钥和对象存储密钥应进入客户密钥管理流程。
- 不同环境使用不同账号和密钥，测试环境凭据不得复制到生产环境。
- 管理员按最小权限原则授权，离职或岗位变化后及时停用账号。
- 日志中不得记录密码、完整访问令牌和模型 API Key。
- 备份文件按生产数据同等级保护，并定期执行恢复演练。
- 系统升级前应核对版本说明、备份关键数据并预留回退窗口。

## 备份与恢复

### 需要备份的内容

| 数据 | 建议方式 | 注意事项 |
|---|---|---|
| PostgreSQL | 数据库原生备份或客户统一备份平台 | 用户、权限、知识库、文档元数据和会话的权威数据 |
| MinIO / S3 | Bucket 版本、复制或对象存储备份 | 保存原始文件和预览文件，必须与数据库保持同一恢复时间点 |
| Elasticsearch | Snapshot | 索引可重建，但快照能缩短恢复时间 |
| `.env` 与服务配置 | 加密配置备份 | 密钥材料应受控保存，恢复后检查权限 |
| 应用版本 | 保留当前及上一稳定版本 | 用于快速回退，不替代数据备份 |

Redis 缓存通常不作为业务权威数据；RabbitMQ 消息也不能替代 PostgreSQL 中的任务状态。恢复时应优先恢复数据库和对象存储，再检查或重建检索索引。

### 恢复验证

备份成功不等于可以恢复。建议至少每季度执行一次恢复演练，验证以下结果：

- 管理员能够登录，用户和权限保持正确。
- 知识库及文档记录完整，原始文件能够打开。
- Elasticsearch 索引与当前文档一致，必要时可重新构建。
- 历史会话和引用仍能查看。
- 新上传文档可以正常完成处理和问答。

## 升级与回退

升级应在约定维护窗口内进行：

1. 确认新版本已经进入正式交付渠道，并记录版本标识和文件校验值。
2. 检查当前健康状态，存在未处理故障时不得直接升级。
3. 备份 PostgreSQL、对象存储和客户配置。
4. 安装到新的 `releases/` 版本目录，不覆盖当前运行目录。
5. 按版本说明执行必要的数据迁移并启动新版本。
6. 重复健康检查和核心业务验收。
7. 验收通过后保留上一稳定版本，用于约定时间内的快速回退。

若升级失败，在确认数据兼容性后切回上一稳定版本，并保留失败日志供排查。不得通过删除数据库记录、跳过迁移或直接修改运行目录掩盖失败。

## 日常运维

建议客户监控以下指标：

| 类别 | 关注内容 |
|---|---|
| 服务可用性 | DocuMind 进程、8089 端口和 `/api/health` 状态 |
| 资源使用 | CPU、内存、磁盘空间、inode 和文件系统读写延迟 |
| 数据服务 | PostgreSQL 连接、Elasticsearch 集群、对象存储容量 |
| 任务状态 | 文档处理成功率、积压数量、失败与重试情况 |
| 模型服务 | 请求成功率、响应耗时、限流和余额或配额情况 |
| 安全审计 | 管理员操作、异常登录、权限变更和密钥更新 |

日志应设置轮转和保留周期。磁盘容量达到客户告警阈值后，应优先清理过期日志和无效临时文件，不能直接删除数据库、对象存储或 Elasticsearch 数据目录。

## 常见问题

### 页面无法访问

依次检查进程是否运行、8089 端口是否监听、防火墙或反向代理是否放行，以及访问路径是否为项目约定入口。使用 HTTPS 时同时检查证书有效期和域名匹配。

### 健康检查提示依赖异常

根据返回的组件名称检查对应地址、账号、网络和证书。PostgreSQL、Elasticsearch、对象存储或模型能力不可用时，不建议继续执行文档上传和正式问答验收。

### 文档长时间处于处理中

检查 RabbitMQ、Embedding、Reranker 和 Elasticsearch 是否可用，同时查看任务积压与应用日志。不要重复上传大量相同文件，也不要直接修改任务数据库状态。

### 能登录但看不到知识库

由管理员检查用户所属租户、角色和知识库授权。DocuMind 默认按授权范围隔离知识库，未授权内容不应通过页面、搜索或问答暴露。

### 回答没有引用或与文档不一致

先确认文档已经处理完成，再检查检索、Embedding、Reranker 和 LLM 服务。验收问题应在文档中有明确依据；系统在没有依据时应说明无法从当前知识库确认，而不是生成看似确定的答案。

## 上线确认

完成部署后，客户项目负责人、系统管理员和实施人员应共同确认：

- 部署架构、访问入口和数据边界符合项目约定。
- 初始管理员及交付密钥已通过安全渠道移交。
- 标准验收流程全部通过，遗留问题已有责任人和完成时间。
- 备份、监控、日志、升级和故障联系机制已经建立。
- 实际运行版本与本次交付记录一致。

本说明书应随产品能力持续更新。客户最终收到的文档以交付日期对应压缩包中的版本为准。
