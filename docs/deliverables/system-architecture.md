# DocuMind 系统架构与业务逻辑说明书

> [!重要] 本说明书介绍 DocuMind 当前产品的系统架构和主要业务逻辑，用于客户技术评审、项目实施、验收及运维沟通。本文描述功能边界和处理关系，不包含源代码、真实账号、密码、令牌或模型密钥。

## 文档目的

DocuMind 是面向企业知识管理场景的文档智能问答系统。系统将企业文档转化为可检索的知识内容，并在用户提问时先查找授权范围内的文档依据，再由大语言模型组织答案，同时保留原文引用和处理轨迹。

本文重点回答以下问题：

- 用户、管理员和平台运维人员分别通过哪些功能使用系统。
- 文档从上传到可问答需要经过哪些阶段。
- 一次问答如何完成检索、重排、生成、引用和记录。
- 租户、角色和知识库权限如何共同形成访问边界。
- PostgreSQL、Elasticsearch、对象存储、Redis 和 RabbitMQ 分别承担什么职责。
- 系统发生重启、任务失败或外部模型异常时如何保留状态并恢复处理。

本文与《DocuMind 独立部署说明书》配套使用：本文说明系统“如何组成、如何运行”，部署说明书说明客户环境“如何安装、配置、验收和运维”。

## 产品角色与使用边界

| 角色 | 主要职责 | 典型操作 |
|---|---|---|
| 普通用户 | 使用已获授权的企业知识 | 选择知识库、发起问答、查看引用、查询历史会话和提交反馈 |
| 租户管理员 | 管理本租户的知识与成员 | 创建知识库、批量上传文档、查看处理任务、配置成员与知识库权限 |
| 平台管理员 | 管理平台级资源和租户 | 管理租户、系统用户、模型及平台运行状态，不直接代替租户用户访问业务数据 |
| 实施与运维人员 | 保障客户环境稳定运行 | 配置依赖、执行健康检查、备份恢复、升级回退和故障排查 |

系统默认使用自身账号体系。只有项目明确启用门户登录模式时，才由门户完成身份接入；进入 DocuMind 后仍需按本地租户、角色和知识库授权计算实际权限。

## 总体架构

### 架构目标

DocuMind 当前架构遵循以下原则：

- 统一入口：浏览器页面和业务 API 由同一个 DocuMind 服务对外提供。
- 数据分层：业务权威数据、原始文件、检索索引和短期状态分别存放在适合的组件中。
- 先授权后检索：任何文档查询和问答都先确定租户与知识库范围，再访问内容。
- 异步处理：上传完成不等于文档立即可问答，解析和向量索引通过可观察的任务阶段完成。
- 依据可追溯：回答保留引用、检索轨迹和 Agent 执行记录，便于用户核对和管理员排查。
- 故障可恢复：文档任务状态持久化保存，服务重启后能够识别并恢复未完成工作。

### 逻辑组件关系

```flow
用户浏览器|HTTPS 页面与 API|DocuMind 应用服务
DocuMind 应用服务|用户、权限、任务和会话|PostgreSQL
DocuMind 应用服务|原始文件与处理产物|MinIO / S3
DocuMind 应用服务|全文与向量检索|Elasticsearch
DocuMind 应用服务|缓存与短期协调|Redis
DocuMind 应用服务|任务通知与可靠传递|RabbitMQ
DocuMind 应用服务|推理请求|LLM / Embedding / Reranker
```

DocuMind 前端使用 Next.js 构建为静态资源，并由 Rust 应用一并提供。客户只需要开放统一访问入口，不需要再维护一套独立前端服务。Rust API 负责认证授权、业务编排、文档处理、检索问答和对外接口。

### 组件职责

| 组件 | 权威职责 | 不承担的职责 |
|---|---|---|
| DocuMind 应用服务 | 页面、API、权限判断、业务编排、任务执行和问答流式输出 | 不把本地进程内存作为业务任务的唯一记录 |
| PostgreSQL | 用户、租户、角色、知识库、文档元数据、处理任务、会话、消息、引用和审计记录 | 不替代对象存储保存大文件，也不作为主要全文检索引擎 |
| Elasticsearch | 文档切片的全文索引、向量索引及混合检索 | 不作为用户、权限或原始文件的权威数据源 |
| MinIO / S3 | 原始上传文件、预览文件和需要持久保留的文件产物 | 不负责权限计算和文档检索排序 |
| Redis | 缓存、短期状态及并发协调 | 不作为必须长期保留的业务记录 |
| RabbitMQ | 异步任务通知和可靠传递 | 不替代 PostgreSQL 中的任务状态和处理历史 |
| LLM | 理解问题并基于检索上下文生成答案 | 不决定用户能够访问哪些知识库 |
| Embedding | 将问题和文档切片转换为同一向量空间中的表示 | 不直接生成最终答案 |
| Reranker | 对候选文档片段进行相关性重排 | 不扩大候选内容的授权范围 |

## 统一访问与请求处理

浏览器访问 DocuMind 后，页面资源和 API 请求进入同一应用服务。典型请求依次经过：

```flow
浏览器请求|携带登录凭证|认证校验
认证校验|确认身份后|租户与权限计算
租户与权限计算|允许操作后|业务服务处理
业务服务处理|读写需要的|数据库 / 存储 / 检索 / 模型
数据库 / 存储 / 检索 / 模型|返回结果|页面或流式响应
```

每次受保护请求都以当前登录身份为起点。服务端不会只依赖页面是否显示按钮，而是再次校验权限；即使用户自行构造 API 请求，也只能在服务端确认的租户和知识库范围内操作。

## 身份、租户与权限逻辑

### 三层访问边界

DocuMind 的业务数据访问由三层条件共同决定：

1. 身份有效：用户账号、登录会话或受控 API 客户端必须有效。
2. 租户匹配：请求中的业务数据必须属于当前身份所在租户。
3. 资源授权：当前角色需要具备相应操作权限，并且目标知识库位于允许访问的范围内。

```flow
登录身份|确定|当前租户
当前租户与角色|计算|操作权限集合
成员与知识库授权|计算|允许知识库集合
操作权限集合与允许知识库集合|共同限制|最终可访问资源
```

数据库查询、文档任务、检索索引和管理 API 均携带租户标识。知识库授权进一步限制用户可以读取或管理的知识范围。租户管理员只能管理本租户；平台管理员和租户身份使用不同的入口与业务边界，避免平台权限被误用为租户数据权限。

### 门户接入逻辑

当项目启用门户登录时，DocuMind 校验门户票据并映射本地用户、租户和角色。最终权限不会超过本地角色与门户授权的交集。门户未提供或未允许的权限不会被自动补足。

未启用门户模式时，系统使用 DocuMind 自身登录页、账号、会话和成员管理逻辑，不依赖外部门户可用性。

## 知识库与文档模型

知识库是企业知识授权和问答范围的基本容器。一个租户可以拥有多个知识库，同一用户可以被授权访问其中一部分。

```flow
租户|包含|知识库
知识库|包含|文档
文档|解析为|内容块与切片
内容切片|建立|全文与向量索引
用户授权|限制|可访问知识库
```

文档记录保存标题、文件类型、文件大小、对象存储位置、当前处理状态和最新处理任务等元数据。原始文件保存在对象存储；解析后的结构、切片和任务记录保存在 PostgreSQL；用于检索的切片副本写入 Elasticsearch。

## 文档上传与处理逻辑

### 批量上传

租户管理员可以一次选择多个文件。页面按文件分别调用上传接口，并以受控并发执行，避免一个超大请求占用连接或因单个文件失败导致整批回滚。

同一批文件共享上传批次标识，但每个文件拥有独立文档记录和处理任务。因此：

- 一个文件失败不会阻止其他文件继续上传和处理。
- 管理员可以查看每个文件的进度、结果和错误原因。
- 可以按批次筛选本次上传产生的任务。
- 重试只作用于选定文档，不会重复处理整批文件。

### 处理阶段

```flow
文件上传|校验通过后|保存原始文件
保存原始文件|创建任务后|等待解析
等待解析|取得执行名额后|文档解析
文档解析|结构提取后|内容清洗
内容清洗|按策略处理后|文档切片
文档切片|调用模型后|向量化
向量化|写入检索库后|建立索引
建立索引|校验成功后|处理完成
```

| 阶段 | 主要工作 | 关键产物 |
|---|---|---|
| 文件校验与保存 | 校验扩展名、内容特征、大小和重复情况，保存原始文件 | 文档记录、对象存储文件、文件校验值 |
| 等待解析 | 创建持久化任务并等待可用执行名额 | 排队任务和批次关系 |
| 文档解析 | 按 Word、PDF、PPT、Markdown 或文本格式提取结构化内容 | 原始内容块、标题、表格及定位信息 |
| 内容清洗 | 规范文本、去除无效内容并计算质量信息 | 清洗后的内容块和质量指标 |
| 文档切片 | 按当前切割策略生成适合检索的片段 | 文档切片、页码或结构锚点 |
| 向量化 | 调用 Embedding 服务生成切片向量 | 与模型维度一致的向量数据 |
| 写入索引 | 将文本、向量和权限元数据写入 Elasticsearch | 可供全文和向量检索的索引文档 |
| 完成 | 汇总切片数、质量和处理结果 | 可问答状态及完整事件时间线 |

### 状态含义

| 状态 | 含义 | 管理建议 |
|---|---|---|
| 排队中 | 文件已保存，任务等待执行 | 正常等待；积压持续增长时检查处理能力 |
| 处理中 | 正在解析、切片、向量化或写入索引 | 查看当前阶段和更新时间 |
| 等待重试 | 前一次执行失败，等待下一次允许执行时间 | 关注外部依赖是否已恢复 |
| 已完成 | 全部阶段成功，文档已可检索 | 可进入问答验收 |
| 完成但需关注 | 主流程完成，但存在质量或内容提示 | 查看质量指标和提示信息 |
| 失败 | 当前任务无法继续 | 根据错误原因修复文件或依赖后重试 |
| 已排除 | 任务因文档删除、版本替换或取消而不再执行 | 无需继续等待 |
| 疑似阻塞 | 运行任务长时间没有心跳或租约已超时 | 检查服务、模型和数据组件状态 |

### 持久化与恢复

任务状态和阶段事件写入 PostgreSQL，而不是只保存在应用内存中。运行任务记录执行者、尝试次数、心跳和租约时间。应用重启后会检查未完成任务和过期运行状态，并在满足条件时重新恢复处理。

任务恢复不表示忽略错误。文件损坏、格式不支持或配置不一致等确定性错误会保留明确失败原因，等待管理员处理；模型限流或暂时不可用等外部问题可在依赖恢复后重新执行。

### 重新处理与版本一致性

管理员重新解析文档时，系统创建新的处理任务，并以最新成功版本作为当前可用结果。新的索引写入完成前，不应把不完整的中间数据暴露为正式知识。文档被删除时，相关任务停止，数据库记录、对象文件和检索索引按业务逻辑清理。

## 智能问答与 RAG 逻辑

### 问答主流程

```flow
用户问题|结合会话上下文|问题理解
问题理解|限定授权知识库|候选检索
候选检索|融合关键词与向量结果|混合召回
混合召回|相关性排序|Reranker 重排
Reranker 重排|组织证据|上下文构建
上下文构建|提交模型|LLM 生成
LLM 生成|核对证据位置|引用解析
引用解析|流式返回并保存|答案、引用与轨迹
```

### 检索范围确定

问答开始时，系统先根据当前租户、用户授权和本次选择的知识库确定检索范围。后续关键词检索、向量检索和引用读取都使用同一授权边界。没有权限的知识库不会因为内容相似而进入候选结果。

### 混合检索

DocuMind 同时利用两类检索信号：

- 关键词信号：适合查找名称、编号、条款、专有词和精确文本。
- 向量信号：适合理解不同表述但语义相近的问题和文档内容。

候选结果融合后交给 Reranker 再次排序，以减少仅凭单一信号造成的无关片段。检索参数可以按客户实际文档和问答效果调整，但调整不会改变权限边界。

### 上下文与答案生成

排序后的高相关片段被组织为模型上下文，并携带文档和片段标识。LLM 根据用户问题、必要的历史会话和检索证据生成答案。模型用于表达和归纳，不作为企业事实的独立权威来源。

当授权知识中没有足够依据时，系统应明确说明无法从当前知识库确认，而不是伪造文档内容或引用。用户仍应根据业务重要性核对原文，尤其是合同、财务、法律和安全类信息。

### 引用与可追溯性

引用解析将回答中的依据关联回文档、切片和原文位置。用户可以查看引用来自哪个文档及对应内容；管理员和诊断工具可以进一步查看检索轨迹、候选来源、耗时和 Agent 处理步骤。

| 记录 | 用途 |
|---|---|
| 会话与消息 | 保留用户问题、模型回答和多轮上下文 |
| 引用 | 将答案依据关联到文档切片及原文位置 |
| 检索轨迹 | 记录召回来源、候选内容、排序和耗时 |
| Agent 轨迹 | 记录问答编排过程和必要的工具调用 |
| 反馈 | 收集用户对回答质量的评价 |
| 审计事件 | 记录重要管理和权限操作 |

## 多轮会话逻辑

用户继续追问时，系统在当前会话内使用必要的历史上下文理解省略信息，例如“上一条中的第二项”或“它适用于谁”。每轮问答仍会重新执行权限判断和知识检索，不会因为历史消息曾出现某段内容就绕过当前授权。

会话记录与租户和用户关联。切换租户、账号或无权限知识库后，不能通过会话接口读取其他范围的数据。

## 管理与可观察性

### 租户管理能力

平台管理员新建租户时填写首位租户管理员信息，系统同时生成一次性邀请链接。平台管理员可立即复制该链接；在租户列表中也可为待加入或已经运行的租户生成并复制管理员邀请，同一邮箱重新生成后旧链接立即失效。受邀人通过链接注册或使用已有账号接受邀请后成为该租户管理员；首位管理员接受邀请时，租户随即启用。

首位租户管理员登录后，可以在“成员与邀请”中继续邀请其他租户管理员和普通用户。新增租户管理员拥有本租户管理权限；普通用户仅能访问明确授权的知识库。租户管理员还可以管理本租户的知识库、文档、文档处理任务、成员、权限和问答记录。文档处理中心汇总排队、处理中、失败和完成任务，并提供批次筛选、阶段时间线、错误详情和处理指标。

### 平台管理能力

平台管理用于查看租户、系统用户、模型配置、系统任务、审计和向量索引状态。平台管理员负责创建租户并交付首位租户管理员邀请，也可以为现有租户补充管理员邀请，但不会因此自动成为该租户成员。每个租户均可在新标签页中直接打开对应租户的登录页面。平台级管理与租户业务访问分离；平台运维应按职责使用专用入口，不共享普通租户账号。

### 健康检查

系统健康检查关注以下必要能力：

- PostgreSQL、Redis、RabbitMQ、Elasticsearch 和对象存储是否可用。
- LLM、Embedding 和 Reranker 是否能够完成真实请求。
- Elasticsearch 当前索引与 PostgreSQL 中有效文档切片是否一致。
- 应用进程和统一访问端口是否正常。

健康检查通过表示关键依赖当前可用，不替代完整业务验收。正式上线仍应执行登录、上传、处理、问答、引用和权限隔离测试。

## 典型异常处理

| 异常 | 系统表现 | 处理原则 |
|---|---|---|
| 文件格式不支持或文件损坏 | 上传被拒绝，或解析任务记录明确失败原因 | 更换有效文件，不通过修改数据库绕过校验 |
| 文档任务长时间无心跳 | 显示疑似阻塞，租约过期后进入恢复判断 | 先检查应用和外部依赖，再决定恢复或重试 |
| Embedding 暂时不可用 | 向量化阶段失败或等待重试，文档不能标记为完整可用 | 恢复模型服务后重试任务 |
| Elasticsearch 写入失败 | 索引阶段失败，保留数据库任务和错误记录 | 修复搜索服务后重新执行，不把未索引文档视为完成 |
| LLM 请求失败 | 当前问答返回明确错误，已持久化文档不受影响 | 检查模型地址、密钥、限流和网络 |
| 用户权限被撤销 | 后续请求无法检索或读取被撤销范围 | 服务端实时按当前授权限制访问 |
| 应用服务重启 | 页面短暂不可用，持久化数据保留 | 服务恢复后检查未完成任务和健康状态 |

## 数据一致性与权威来源

| 数据类型 | 权威来源 | 可恢复或重建关系 |
|---|---|---|
| 用户、租户和权限 | PostgreSQL | 必须备份，不应从缓存反推恢复 |
| 文档元数据和处理任务 | PostgreSQL | 决定文档当前版本和处理状态 |
| 原始文档 | MinIO / S3 | 与数据库记录共同用于重新解析和恢复 |
| 文档切片 | PostgreSQL | 可用于核对和重新建立检索索引 |
| 检索索引 | Elasticsearch | 应与有效切片一致，异常时可核对或重建 |
| 缓存和短期协调状态 | Redis | 不作为业务恢复的唯一依据 |
| 异步通知 | RabbitMQ | PostgreSQL 任务记录仍是处理状态依据 |
| 会话、消息、引用和轨迹 | PostgreSQL | 用于历史查询、问题核对和审计 |

备份恢复时应优先保证 PostgreSQL 和对象存储处于一致时间点，再检查 Elasticsearch 索引。只恢复搜索索引而没有业务数据库和原始文件，不能构成完整业务恢复。

## 部署与扩展边界

DocuMind 可以采用单机一体化、应用与数据分离或经过容量评估后的高可用部署。无论采用哪种方式，逻辑组件职责和权限边界保持一致。

首期应根据实际用户数、文档量、每日新增量和模型吞吐选择最小可用配置。出现以下可测量信号后再考虑扩展：

- 文档处理队列持续积压，且模型和数据组件没有故障。
- 问答并发增长导致响应时间持续超过项目目标。
- Elasticsearch 索引、对象存储或数据库容量接近规划阈值。
- 单节点故障恢复时间不能满足客户业务连续性要求。

扩展应用实例前，应确认任务领取、共享存储、数据库连接、模型并发和统一入口均按多实例方式配置。不能仅复制进程而忽略任务幂等和共享数据一致性。

## 架构验收建议

客户技术评审和上线验收建议至少覆盖：

1. 使用租户管理员批量上传多个不同格式文档，确认每个文件都有独立任务和阶段记录。
2. 对正常文档确认解析、切片、向量化和索引全部完成。
3. 上传损坏文件，确认失败原因可见且不会影响同批其他文件。
4. 对文档中的明确事实提问，确认答案、引用和原文一致。
5. 对文档中不存在的信息提问，确认系统不会伪造依据。
6. 使用两个租户和不同授权用户交叉测试任务列表、检索、会话及引用隔离。
7. 重启应用服务，确认历史数据保留且未完成任务能够恢复或给出明确状态。
8. 执行健康检查和向量一致性检查，确认 PostgreSQL 有效切片与 Elasticsearch 索引一致。
9. 检查管理操作、失败记录和问答轨迹是否满足项目审计要求。

## 术语说明

| 术语 | 说明 |
|---|---|
| RAG | 检索增强生成；先从授权知识中查找依据，再让模型基于依据生成回答 |
| Chunk / 文档切片 | 从文档中切分出的检索基本单元，保留所属文档和定位信息 |
| Embedding | 将文本转换为向量表示，用于语义相似度检索 |
| Reranker | 对初步召回的候选片段重新计算相关性并排序 |
| LLM | 大语言模型，用于理解问题和组织自然语言答案 |
| Agent | 负责协调检索、上下文、模型和引用处理的问答执行逻辑 |
| 租户 | 相互隔离的组织数据空间 |
| 知识库 | 租户内组织文档、授权和问答范围的容器 |
| 处理任务 | 记录文档解析到索引全过程的持久化工作单元 |
| 租约与心跳 | 用于识别任务由谁执行以及执行者是否仍然存活的运行状态 |
| 混合检索 | 综合关键词和向量相似度的候选召回方式 |
| 引用 | 回答与原始文档依据之间的可追溯关联 |
